# 9.30 剩余业务前端浏览器验收

范围对应需求文档“本次版本剩余未完成内容”的敏感词、登录方式/账号绑定、OAuth 授权范围与图片验证码前端。使用真实业务页面和请求层；测试供数与故障来自独立本地 mock，不代表后端、真实 IdP 或生产权限配置已验收。

## 启动与复跑

在本工作区运行 `pnpm run dev:release0930-mock`，默认地址 `http://localhost:3102`。这个专用环境才启用 `/api/mock/release0930/*` 控制接口，生产与普通开发环境不启用。

运行 `pnpm run e2e:release0930`。套件创建一个 ego-browser 任务空间，成功后关闭它。若复用当前任务的空间：

```sh
E2E_BASE_URL=http://localhost:3102 \
E2E_TASK_SPACE_ID=4 E2E_PAGE_LABEL=p3 \
pnpm run e2e:release0930
```

共享空间不会被套件关闭。使用 `E2E_CASES=sensitive,auth,idp,scope,captcha` 可选择用例组；套件每组重置本地假数据，并通过真实密码登录建立前置身份。串行运行，避免另一个用例覆盖服务器供数或抢占浏览器。

## 断言范围

- `sensitive`：新增与编辑 DISCONNECT/REPLACE、停用、保存失败保留弹窗/原值、删除确认、只读权限隐藏新增并禁用修改。
- `auth`：编辑时登录方式类型锁定、密钥留空时请求不携带密钥、自动跳转全租户唯一、停用联动清除自动跳转。
- `idp`：`local=1` 兜底、PC 用户代理过滤公众号入口、协议确认后授权回跳、未登录自动跳转、`idpError` 不循环重定向、账号绑定错误/成功返回并清理一次性参数、唯一身份未设密码时拒绝解绑、解绑成功刷新列表。
- `scope`：三方应用和全栈应用在 Pending 状态只改地址时省略 scopes，从待审 B 改回生效 A 时显式提交 A；管理员通过后回详情检查生效范围，拒绝后回详情检查原因和原范围。
- `captcha`：密码登录错误后换图/清空并使用新图成功登录、验证码首次发码携带登录页图码、首次发码失败后立即重发且使用新图、设置重置密码和绑定邮箱失败后换图/立即重试、关闭图码后五入口隐藏图码并省略相关请求字段。

业务写入全部通过页面按钮完成。控制接口仅重置假数据、配置权限/租户开关或注入一次失败；验收同时读取服务器记录验证实际请求参数。请求记录隐藏密码、token 和密钥，不打印敏感内容。

Ask Question 与 IM 关联任务的浏览器验收由各自专项套件负责，不包含在这里的通过数中。真实接口、菜单/资源种子、真实 IdP 与客户端宿主行为仍需独立联调。
