# F2 飞书 9/24 文件树刷新：实现与证据

## 任务卡

- 来源：研发组 9/24 冯飞，编辑/新增文件时刷新，普通工具调用不应一直刷新；编辑后再刷新。
- 禅道关系：父代理全量 2497 条未找到同义工单，2419 后端搜索另属问题。本次仅 PC/Web；移动端排除。
- 难度中等：会话 SSE/React 副作用熟练的模型或 agent；复用既有文件树面板。
- 修复：live/sub/legacy 共用完成后文件变更语义；AppDevPro runtime 补共享树与选中文件正文刷新资源，2s 节流，完成兜底保留。
- 边界：终端任意脚本不能静态判定所有副作用，除了明确简单只读命令，结束时保守刷新；失败命令也可能部分写文件。未知工具未给变更信息时依赖 FINAL 兜底。

## 可复现因果与测试

- 原 runtime 搜索也 dispatch 文件刷新。先改直接回归，搜索开始/结束、读取完成、写入开始、pwd 完成五项红灯，其余 47 项绿。
- 独立复审抓到 AppDev 资源仅在 session 首次捕获。旧依赖 active/id 的节流闭包在隐藏转活跃、会话切换后失效；四条真实 React hook 回归先全红，再改稳定回调、render 最新 ref、布局阶段 cancel、卸载守卫后全绿。
- F2 定向：4 文件 / 100 项通过；独立评审无剩余 Important（父代理也独立跑 hook+domain）。
- 完整会话门在稳定 hook 前：104 文件 / 978 项通过。稳定 hook 后由父代理统一集成再跑必需完整门，避免重复多个 worktree 全量。
- 分层门：2900 模块 / 12703 依赖零新增违规，97 存量忽略。
