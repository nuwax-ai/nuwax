# 0930 License 前端一期规格

日期：2026-10-02。意图：[License intent](../plans/20261002-release0930-license-intent.md)。真实接口未就绪，以下是前端临时投影，不声称后端已有接口或签名格式。

## 状态与权限

`LicenseSnapshot` 包含 `state: NOT_INSTALLED | VALID | EXPIRED | INVALID`、授权主体、脱敏编号、可选生效/到期/更新时间、`canImport` 和只读 `features`。功能项包含 code、名称、enabled 和可选原因，具体名单由明确契约返回。

请求层另区分 loading、ready、unavailable、unauthenticated、forbidden、network、invalid-response。未接入、权限失败或读取失败不能伪装为未安装/过期。授权状态由 provider 决定，前端只格式化时间，不本地判签或根据时钟改写状态。

管理页临时路径 `/system/config/license`，查看/更新分别需要 `license_query`、`license_import` 资源权限；后者还受可用 provider 和 `canImport` 约束。管理员角色不绕过资源权限。普通 403 与专门到期反馈区分。

## 配置操作

文件导入是本轮可调整的前端提案，用户尚未确认最终输入方式。选择非空、最多 1 MiB 的原始文件，手动提交给专用 provider；不把文件交给通用 CDN 上传或记录到日志。失败保留当前快照与输入以便重试，成功以 provider 回包刷新，不在客户端伪造激活成功。

本地 mock 使用 JSON 最小快照 fixture 证明页面更新流程，解析后严格投影字段并原子替换状态；这不是实际签名授权格式。普通开发和生产 provider 仍明确不可用，后续按实际契约实现文件传输与服务端判定。

## 功能管控边界

可复用授权判定只消费明确的功能 code。已注册的受控功能在授权缺失/无效/不可读取时不可执行；不能把未知状态当作已授权。新账号或重新加载失败不能复用旧账号的授权成功值。

具体受控功能与隐藏/禁用规则待确认；不会仅凭商业版标识把全站加入限制名单。登录、图形验证码、账号修复、退出登录、授权查看和授权更新不纳入全局阻断。mock 示例功能只证明前端 gate 可用，不作为最终业务名单。

## 接入与并发

生产/普通开发默认 provider 明确 unavailable。专用 `release0930Mock` 定义明确编译开关后才选择 local mock provider；网络/401/403 不静默切换假数据。临时 mock 端点位于 mock 控制命名空间，真实 provider 不发明后端 URL。

controller 统一管理读取、更新和请求代次；后发读取/更新、账号变化、卸载使旧响应失效。更新结束前重复提交被阻止；迟到读取不覆盖更新后的快照。读取失败清除可执行授权判断，页面区分此前展示信息与当前读取失败。

## 验证

状态与未知字段、资源权限、错误分类、请求乱序/卸载失效、更新成功/失败、已注册功能 fail closed 均需定向测试。浏览器验管理员/只读/无权用户、首屏错误重试、不同状态、更新恢复与功能 gate；生产默认不可用及 fixture 排除需构建取证。真实接口/权限种子和部署单独验收。
