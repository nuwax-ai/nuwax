# 意图：项目、任务及会话跨页面状态同步

- 日期：2026-09-16 　发起人：产品/前端
- 状态：已接受（用户，2026-09-16）

## 问题

单栏导航长期挂载，常规项目、全栈项目、任务会话及其详情页分别维护本地数据。项目或会话在另一入口被创建、改名、删除，或会话执行状态、自动标题发生变化后，侧栏、详情页和管理页不能稳定同步，通常要重新进入页面才恢复正确状态。

现有同步通道分散在 `window.CustomEvent` 与 `eventBus`，只覆盖部分任务列表；项目子会话、项目管理页、历史页和当前详情标题存在遗漏。

## 预期结果

- style1、style2、style3 下的项目/任务侧栏都能及时显示最新名称和会话状态。
- 项目或会话创建、改名、删除后，当前仍挂载的相关页面及时同步。
- 首条消息自动生成会话标题、IDE 自动生成项目名称后，侧栏和当前详情标题同步更新。
- 快速连续更新、请求途中发生更新时，不被较旧的接口响应覆盖。
- 旧事件发射方在迁移期继续可用，不影响 `conversationPageCacheManager` 等既有消费者。

## 受影响的能力面

- 首页项目/任务侧栏 `NewHomeSection`、`ProjectPanel`。
- Chat、AppDevPro、ConversationAgent 等会话入口和 legacy/runtime 双线。
- SpaceProjectManage、历史会话页、项目详情页。
- 会话及项目创建、更新、删除成功后的前端通知协议。

不修改后端接口，不新增对外网络协议。

## 约束

- 各页面继续拥有自己的列表 state；事件仅携带补丁或失效信号。
- 新协议必须带明确实体身份，项目 ID 按字符串传递，避免大整数精度问题。
- v1 只处理名称、图标、taskStatus、创建、删除；收藏、置顶、归档和跨标签页同步不在本期。
- 会话路径改动必须通过 `test:conversation`，且不得新增分层依赖违规。

## 开放问题

- 无阻塞项。跨标签页与多 WebView 同步后续若有需求，再扩展 `BroadcastChannel` 或宿主桥。
