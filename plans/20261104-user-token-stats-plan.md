# 计划：用户 Token 消耗查询（下一版本）

## 目标与决定

- 本需求属于下一版本，独立分支 `codex/user-token-stats` 基于 `feat-2026.11` 开发，PR 仍指向该分支；不合并或部署当前发布线。
- L5 本段实现按指定用户、时间范围查询 Token 消耗及分页明细；全局用户排名需后端聚合/排序契约，不以当前页排序冒充排名。
- 保留现有平台模型监控口径。`userId=-1` 是平台统计账户，不能标作全部用户；新增用户视图使用正整数用户 ID、`CONSUMPTION` 和模型明细，汇总只展示消费组，不混入销售收入。
- 用户 ID 全程以字符串保留，支持 int64，不能经 Number 转换后查询另一个用户。首期直接输入用户 ID，复用现有统计权限和路由，不依赖用户管理额外权限。

## 实施与验证

- 页面统一管理待提交筛选和已生效查询；翻页使用已生效筛选，查询/重置回第一页。未指定用户时不发送全量查询。
- 汇总和明细使用同一查询快照；切换用户、范围或视图后取消旧请求，丢弃迟到结果。失败清空本轮数据并提供重试，不把失败显示成零消耗；成功无记录才展示零和空明细。
- 复用 `/api/system/bill/resource-stat/summary`、`detail`，用户视图明细按 `targetType=Model` 查询；Token 总量含非缓存输入、缓存输入、输出，继续使用既有精度处理。
- 补充查询隔离、分页条件、失败重试、零数据、平台/用户口径和长 ID 回归；运行受影响测试、类型诊断及分层检查，用 ego-browser 验证真实页面与测试接口。

## 未完成事项

- 全局排名不在本段实施范围，仍待后端聚合/排序契约。
- 本段为下一版本源码候选，尚未合并、部署或完成 Nuwax 客户端安装包验收。
