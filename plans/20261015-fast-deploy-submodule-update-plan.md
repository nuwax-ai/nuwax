# 快速提测自动更新子模块

2026-10-15 用户决定：`deploy_test.sh` 不再因子模块检出版本与登记版本不同而拦截提测，提测默认使用最新子模块。本决定替代 20261014 快速通道计划的 D2。

状态：已实现并验证（2026-10-15）。

## 实现范围

1. 预检区分主仓/子仓文件改动与未暂存的 gitlink 偏差。前者仍停止并保留现场；后者先按登记提交对齐，避免切分支被误拦。
2. 汇合到 test 后，调用 `upgrade:micro-apps -- all`，复用快进检查、适配 patch/overlay 预检和失败回滚。成功后提交 gitlink 与 adapter.pin，随后执行现有质量门及构建。
3. 不修改升级工具和远端 dev 推送规则；只读演练仅展示升级命令。
4. 同步 AGENTS、提测 runbook 和微应用 runbook 的现行行为说明，旧计划保留历史并标注替代关系。

## 验证

- 本地临时仓库回归：检出版本偏差自动升到最新；gitlink/pin 与实际构建来源一致；返回起跑分支后对齐该分支登记版本。
- 主仓改动、子仓文件改动与已暂存的 gitlink 均保留并拒绝操作；升级/适配失败时不得构建或推送。
- 有版本偏差时 DRY_RUN 不改变 refs、index、HEAD 或子仓内容。
- `bash -n deploy_test.sh`、`npm run test:scripts`、`npm run lint:arch`；不重复发布上一轮已成功的测试产物。

## 验证结果

- 新用例先复现旧行为：版本偏差在预检失败，远端补丁不兼容却仍发布旧版本；修复后快速通道 20 项全部通过。
- `npm run test:scripts`：doctor 4、提测 49、微应用构建/升级 75、类型门 19，共 147 项通过。
- `npm run lint:arch`：零新增违规，97 条已登记存量豁免。
- 真实仓库执行 `DRY_RUN=1 sh deploy_test.sh`，前后 refs、索引摘要、工作区状态、递归子模块版本均一致；shell 语法与 diff 检查通过。
