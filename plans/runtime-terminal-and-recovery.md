# 计划：会话终端与执行恢复

## 目标与决定

- NW-026：恢复当前分支未包含的跨会话保活；会话内允许显式创建、切换、关闭多个终端。连接按页面会话/沙箱及终端编号隔离，不改变 ttyd 服务端协议。仅 Chat / ConversationAgent 启用，多环境 AppDev 控制台保持既有契约。
- 常驻页面切换只隐藏，不销毁连接；关闭终端、切沙箱、页面实例淘汰/登出时释放。打开终端占用常驻页保留资格，不受智能体终态 60 秒宽限影响；容量仍为 5 页，优先释放无终端页，全有终端时按既有上限回收并提示。网页刷新和真实断网后的 shell 恢复需要服务端支持，本次保留重连语义。
- NW-081 仅交付真实 reconciler 失败探针证实的终态/恢复缺陷修复；原会话 1731371 的后端运行及落库回答未取得，原现场按“不能复现先搁置”处理。
- NW-262 原始过度执行链无法复现，已停止推测性改造并搁置；已有目录任务护栏原型仅保存在 ACP 独立候选分支，不纳入本轮接线或缺陷修复交付。
- NW-335 是明确防御需求：在自有 ACP/Bash 接入点对影子搜索加有界进程监测、最终超时与安全回退。使用总控提供的 ACP 独立工作区；不改线上 Agent/模型/技能配置或用户全局 shell。macOS 使用 RSS 事后熔断，Linux 硬限额及正式包另验，Windows 暂保留既有执行方式。

## 实施与验证

- 复用现有终端 WebSocket/xterm 实现及保活开关；多实例独立重连，关闭停止重连与计时器。
- 运行会话保护网及受影响组件回归；ego-browser 独立 TaskSpace 通过隔离 ttyd/运行快照夹具验证可见行为、串线与清理。
- 本组证据和可恢复状态保存在仓外 groups/05-runtime。真实服务端、正式客户端包与上线状态独立记录，未验证保持待验收。
