# 实施计划：client-conversation-fast-switch

- 对应 spec：`specs/client-conversation-fast-switch.md`
- 状态：代码已实现，待真实客户端登录态验收

## 改动

1. 为整页实例建立独立生命周期管理器，不改变现有右侧工作区缓存语义；采用 5 个总实例、2 个 IDE、终态 60 秒、运行中优先的释放规则。
2. 让 Chat、Agent 开发页和全栈 IDE 有固定实例身份与激活状态；先隔离会话 model、流式连接、轮询、异步回包及卸载清理，再接入商业客户端常驻宿主。
3. 隐藏页保留必要数据处理，暂停高频界面工作；增加热切耗时、实例/连接数和内存走势观测，并按测量结果处理长列表渲染。

## 验证

- 缓存生命周期纯函数与边界测试，三入口切换、异步迟到和资源释放组件测试。
- `npm run test:conversation`、改动路径类型检查与分层依赖检查。
- 真实客户端登录态验证 A→B→A、会话 → 菜单 → 会话、跨工作台切换、超限恢复和释放。

## 风险与回退

会话 model 已按常驻实例隔离，并覆盖并发测试；默认浏览器行为与 style1/2 保持原样。若客户端实测暴露资源问题，可将商业宿主的整页保活入口回退到原路由渲染。隐藏页的流式数据仍可能触发 React 提交，需要在真实客户端观察 CPU 与内存曲线。

## KeepAlive 插件评估（2026-09-24）

可把插件作为挂载层的后续替代方案，但本次维持现有整页宿主与生命周期管理器。插件只解决组件保活，不能代替本项目需要的 Umi model 实例隔离、5 页/2 IDE 配额、运行状态驱动的释放、登出/删除清理与 VNC 换主。当前代码已经覆盖这些规则并有对应测试；现有依赖中也没有路由 KeepAlive 插件。若后续实测发现宿主挂载成本或兼容问题，再用真实客户端 A→B→A 耗时、峰值内存和隐藏页 CPU 数据评估局部替换，迁移时仍保留生命周期管理器。
