# 0930 商业版 License 前端意图

日期：2026-10-02。用户选择继续第 13 条 License，并允许接口未就绪先走 mock。工作区为 remaining，保留主检出的并行改动。

## 目标

管理员可查看当前授权状态、有效期及功能授权清单，并完成授权更新；普通用户在明确的受控功能不可用时得到可理解的反馈。登录、验证码、账号修复、退出登录和管理员授权修复入口必须可访问。

## 当前证据

- 测试 OpenAPI 当前 1205 个路径，未见 license/licence/entitlement；`commercialEdition` 只有版本标识，不能当作授权状态。
- `/license-expired` 复用 403 页面；普通权限拒绝也复用此页，当前文案固定为许可证过期，需区分。
- 配置入口建议 `/system/config/license`，沿用现有资源权限，不因角色名为 Admin 而绕过权限。

## 一期范围

- 独立授权状态页：未安装、有效、过期、无效；读取中、读取失败及服务未接入分别呈现。
- 显示授权主体、脱敏编号、生效时间、有效期和 provider 返回的功能授权清单。未知字段显示缺省值，不根据本机日期或商业版标识猜测有效性。
- 授权更新操作待用户选择文件导入、文本输入或只读。本轮推荐原始文件导入/更新；前端不本地验证签名，不通过通用 CDN 上传授权文件。
- 受控功能名单、入口隐藏/禁用规则待补充。先定义可复用的授权判定与反馈，mock 中的样例不等于最终产品名单；不擅自全站禁用。
- 默认真实 provider 明确不可用；只有专用 release0930Mock 环境启用 fixture。真实接口失败不能静默降级 mock。
- 真实 API 与菜单种子、服务端签发/校验另行对齐；前端 mock 通过不等于正式授权 enforcement 已完成。

## 验收

权限拒绝与 License 状态区分；首次失败不伪装为空/过期；刷新失败清除可执行授权判断并保留明确的错误反馈；更新失败不修改当前授权，成功使用 provider 新快照；失效 → 恢复更新后重算能力。临时接口与任何原始授权内容不能出现在日志/请求记录中。

## 待确认

1. 配置方式：文件导入/更新（推荐）、文本输入，或仅查看。
2. 本期明确的受控功能和失效反馈策略；恢复入口不纳入阻断。
