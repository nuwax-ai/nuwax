# 会话渲染规则维护性重构

## 目标与边界

以当前确认的行为为基准：连续工具合并、思考打断工具组、尾部活动组展开、超越后收起、手动选择保留；普通 live 与 sub 续接一致。过程说明随过程折叠，最终回答独立显示。保持 Todo 去重、OpenUI 挂载路径、偏好过滤及零秒耗时规则。

本次是 presentation-v2 模块内部职责整理，不改数据接口、会话续接控制器、消息生命周期、视觉样式或产品行为。

## 实施

1. 提取纯展示模型：先分组、再过滤、按过程段关联展示项；组件不再重复编排节点。
2. 提取折叠状态与转换规则：节点、工具组、过程段的手动操作和活动切换统一管理；React 只绑定状态及事件。
3. 建立一份当前有效的规则文档，以规则编号对应代码入口和测试；原有重复文档改为入口或架构说明。
4. 复用既有 live/sub、正文边界、Todo 和 OpenUI 回归，补状态转换及隐藏边界测试；运行会话质量门、域类型检查和依赖检查。

## 完成条件

- 展示组件仅负责布局与事件绑定，规则函数不依赖 React、DOM 或网络。
- 同一条规则只有一个实现入口；文档明确活动状态、默认值、手动覆盖和状态转换的优先级。
- 已确认的行为测试保持通过，真实页面回放覆盖工具分组和折叠交互。

## 实施与验证记录

- `traceViewModel.ts` 承接分组后过滤与过程段关联；`traceDisclosureState.ts` 提供纯状态转换；`useTraceDisclosure.ts` 绑定 React，组件保留布局、资源事件与隔离计时器。
- `docs/conversation/rendering-rules.md` 为当前规则唯一维护入口，旧总览改为链接。
- 会话质量门：114 个文件、1196 项测试通过，含 live/sub、Todo、OpenUI 和新增状态转换回归。
- 会话域类型检查：124 个文件零诊断；域外 289 项既有诊断不作为本域门。
- 依赖检查：3023 模块、13152 条依赖无新增违规（97 项既有豁免）。
- ego-browser 在真实页面的本地数据回放通过：尾组默认展开，手动折叠跨增量保留，思考打断并自动收起，重开旧组后新组到达仍保留选择。回放数据已清理，TaskSpace 已结束。
- 浏览器验证没有发送真实后端消息；手机发消息、PC 续接的完整链路尚未重新实测。
