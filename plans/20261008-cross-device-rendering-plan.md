# 手机消息触发 PC 自动续接的渲染修复

- 场景：手机继续同一会话，PC 自动同步快照并订阅恢复流。旧本地回答可能被追加到手机新轮，正文整体替换延迟到下一帧；快照与重放中同一工具执行会生成重复节点 key。
- 实现：按用户消息划定轮次并保留回答归属；Markdown 首次挂载和整体替换在绘制前同步，流式追加仍按帧合并；同轮相同 executeId 的工具节点合并为一个，保留稳定位置及最新状态。
- 范围：共享快照合并函数、Markdown hook、V2 投影。沿用现有 API 与恢复流语义。
- 验证：中间快照回答归属、首帧与 StrictMode 回归、快照与重放工具去重；会话质量门、域类型检查、双数据线正常发送/恢复浏览器回归。真实手机发送的验收仍需设备确认。
- 用户确认的展示规则：自动续接不额外插入“渲染中”一行，已移除该提示的组件、状态透传及语言词条。
- 收尾展示规则：当前轮已收到 FINAL_RESULT 时，即使 taskStatus 暂时残留 EXECUTING，也不再显示“智能体正在执行，请稍等”；判断止于当前 user，上一轮终态不影响下一轮。补齐结束事件成功、失败、未标明 success、尾部空占位及新轮边界的回归，1172 项会话测试通过，类型检查 0 错误，ESLint 通过，runtime 自动续接浏览器重放未出现收尾等待提示。

## 实际 AppDevPro 复查

- 用会话 1695398 的消息重放 PC UUID 终态、本轮无 index、手机 user-only 快照，实际页面可复现旧回答出现在手机用户消息下。
- 根因在 `preserveOptimisticMessageTail`：只判断全列表末条是否已完成，旧轮 assistant 会被追加到手机新轮。改为按匹配的用户消息划定轮次；已落库的旧回答丢弃 UUID 副本，尚未落库的回答插回所属 user 后、新 user 前。
- 补齐 user-only / loading 占位 / 重复指令 / 多轮 UUID / SSE 已换服务端 ID，以及消息仓和真实 V2 渲染器的全过程回归。
- 验证结果：移除额外提示后，1167 项会话测试通过，会话域类型检查 0 错误，diff 检查通过；自动续接浏览器回归在 runtime 与 legacy 数据线均未出现“渲染中”。回答归属修复的 ESLint / Prettier 检查通过，实际 AppDevPro 页面在两条数据线均重放上述四个阶段，旧回答始终只出现一次，手机新轮不含旧正文。重放未发送新的真实指令，手机实机发送验收仍待确认。

## 1695407 的 sub 重放与侧栏续接补充

- 用户日志显示手机新 USER 后，PC sub 在约半秒内收到终态并关闭，之后再次等终态轮询。历史接口最终返回的新回答与截图中重复的旧回答不同；日志没有事件正文，不能仅据此断言服务端回放内容。
- 代码回归证实：新 USER 已在历史中时，旧轮 FINAL_RESULT 会无条件写入新占位并触发完成状态。新增共享 sub 事件归属校验，使用旧消息 ID、旧 requestId、早于当前 USER 的事件时间排除已确认的旧轮事件；没有归属证据的事件仍兼容，相同正文不作为去重条件。
- 当前轮终态解析止于 USER，避免新 USER 尚无 assistant 时继承上一轮完成状态。
- 侧栏已接受的执行态快照通过独立观察事件唤醒会话详情校验；目录执行状态补丁也可唤醒。校验与可见性恢复共用单飞锁，旧轮询代际失效，本地发送/切会话期间回包丢弃，失败消费拒绝并允许重试。
- 一旦详情证实外部执行，即使 model 暂留上一轮 COMPLETE，sub 秒关后的轮询也恢复正常执行态间隔，不再等 30 秒；终态确认后恢复退避。
- 真实 AppDevPro 页面（1695407，runtime 数据线）用浏览器本地详情与 SSE 夹具串联验证：侧栏观察 → 15ms 发起 sub → 旧 FINAL_RESULT 被拦截 → 约 5.4s 再次 sub → 新回答流入 → 正常结束。旧正文仅一份，新轮无旧正文，结束无“渲染中”及“智能体请稍后”。未发送真实开发指令，真实手机发送仍待设备验收。
- 验证：1182 项会话测试通过；另运行目录事件测试（含观察通知不反向产生目录补丁）；会话域 120 个文件类型检查 0 错误，ESLint、Prettier 与 diff 检查通过。浏览器夹具已清理并重载真实历史。
