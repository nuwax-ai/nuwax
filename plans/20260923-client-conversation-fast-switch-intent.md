# 意图：客户端会话与工作台快速切换

- 日期：2026-09-23
- 状态：已接受（用户确认覆盖所有会话入口、整页即回和资源取舍）

## 问题

PC 端 style3 采用单栏侧边导航；侧栏虽常驻，路由内容仍会因切换而重新初始化。已有缓存只覆盖 Chat 右侧工作区与草稿，无法让运行中会话、Agent 开发页和全栈 IDE 在切回时整页即回。多页同时挂载又会触碰全局单例会话 model，并增加渲染、连接和内存开销。

## 预期结果

- 运行中会话在项目、任务和其他菜单间切换后快速回到原消息、滚动、输入、流式进度及整个工作台状态。
- 多会话状态与副作用互不覆盖；隐藏页能继续接收运行结果，但不做无用的界面渲染。
- 缓存有明确上限与释放时机；超限页可从服务端可靠恢复。

## 受影响的能力面

所有 PC style3（商业客户端与桌面浏览器）下的普通 Chat、Agent 开发工作台、全栈 IDE、左侧项目/任务列表、会话运行时、工作区缓存与性能观测。

## 约束

- 同时最多保留 5 个整页实例，其中 IDE 工作台最多 2 个；运行中优先、当前页受保护。
- 隐藏且转为终态的实例保留 60 秒，容量不足时可提前释放。VNC 全局唯一。
- style1/style2 与移动端维持原有路由行为；桌面浏览器 style3 与商业客户端 style3 使用同一保活规则。
- 会话路径改动需通过 `npm run test:conversation`，交付前需要真实客户端登录态验收。

## 开放问题

无产品决策待确认；各入口的单例 model 隔离是实施前置技术条件。
